  <action>
Create a `Dockerfile` in the project root that builds a production-ready container for the Fake News Detection API.

The Dockerfile must:
1. Use `python:3.13-slim` as the base image (small footprint, matches project Python version)
2. Set working directory to `/app`
3. Copy `requirements.txt` first (for Docker layer caching — dependencies change less often than code)
4. Run `pip install --no-cache-dir -r requirements.txt`
5. Copy the application files: `model.pkl`, `app.py`, `model.py`, `preprocess.py`
6. Expose port 5000
7. Use `waitress-serve` as the entrypoint (not Flask dev server — per STACK.md guidance)

Full Dockerfile content:
```dockerfile
FROM python:3.13-slim

WORKDIR /app

# Install dependencies first (layer caching)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code and model
COPY model.pkl .
COPY app.py model.py preprocess.py ./

EXPOSE 5000

# Use Waitress for production-grade local serving
CMD ["waitress-serve", "--listen=0.0.0.0:5000", "app:app"]
```

Key design decisions:
- `python:3.13-slim` — matches project's Python version requirement, smaller image
- `--no-cache-dir` — reduces image size by not storing pip cache
- `requirements.txt` copied separately — Docker caches this layer unless dependencies change
- `waitress-serve` — per STACK.md: "Flask dev server in Docker" is listed under "What NOT to Use"
- `0.0.0.0:5000` — binds to all interfaces so port mapping works from host

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host→container (port 5000) | Container binds to 0.0.0.0:5000 — accessible from host network. Local-only API, no auth. |
| build context→image | Docker build copies local files into image. .dockerignore limits what enters. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Information Disclosure | Docker image layers | accept | Image contains model.pkl and source code. For local-only use this is acceptable. If distributing the image, model.pkl would be exposed — out of scope for local API. |
| T-02-04 | Denial of Service | Waitress server | accept | No rate limiting (per PROJECT.md constraints). Local-only API — DoS risk is limited to localhost. Waitress handles concurrent requests better than Flask dev server. |
| T-02-05 | Supply Chain | python:3.13-slim base image | transfer | Trust official Python Docker Hub image. Pin to specific digest in production if needed; tag reference is sufficient for local use. |
</threat_model>
